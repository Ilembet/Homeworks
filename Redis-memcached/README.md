## Задание 1. Кеширование

Кеширование хранит результат дорогой операции в быстром хранилище (обычно в оперативной памяти), чтобы не повторять эту операцию при каждом запросе. Вот какие проблемы оно решает:

- **Высокая нагрузка на базу данных.** Одни и те же запросы (например, список товаров или главная страница) выполняются тысячи раз. Результат кладётся в кеш, и БД обращаются только при промахе.
- **Медленные ответы.** Чтение из памяти занимает доли миллисекунды, а сложный SQL-запрос с JOIN и агрегацией может идти секунды. Кеш заметно сокращает время отклика.
- **Тяжёлые вычисления.** Отчёты, рендеринг шаблонов, обработка изображений и ответы ML-моделей можно посчитать один раз и переиспользовать.
- **Медленные или лимитированные внешние API.** Кеш уменьшает число обращений к сторонним сервисам (курсы валют, погода, геокодинг), экономит квоты и деньги и помогает, если сервис временно недоступен.
- **Пики трафика.** При наплыве пользователей (распродажа, вирусная новость) кеш принимает основную часть запросов, и бэкенд не падает.
- **Хранение сессий.** Сессии пользователей в Redis или Memcached доступны всем серверам приложения, что удобно при горизонтальном масштабировании.
- **Ограничение частоты запросов (rate limiting).** Счётчики с TTL в Redis позволяют ограничить, например, число попыток входа в минуту.
- **Нагрузка на сеть и каналы.** CDN и браузерный кеш отдают статику (картинки, JS, CSS) с ближайшего узла и разгружают основной сервер.

> **Обратная сторона кеша:** данные могут устареть, поэтому нужны TTL и стратегия инвалидации.

## Задание 3. Удаление по TTL в Memcached

Записываем ключи с TTL 5 секунд и проверяем, что спустя 6 секунд они удалились:

```bash
printf "set key1 0 5 6\r\nvalue1\r\nset key2 0 5 6\r\nget key1 key2\r\n" | nc -q1 localhost 11211
sleep 6
printf "get key1 key2\r\n" | nc -q1 localhost 11211
```

Формат команды: `set <ключ> <флаги> <TTL в секундах> <длина значения в байтах>`. `value1` занимает 6 байт, поэтому везде указано `6`.

Первый `get` вернёт оба значения, а второй, через 6 секунд, только `END`. Это и есть доказательство, что ключи удалились.

## Задание 4. Запись данных в Redis

Установка и запуск Redis:

```bash
sudo apt install -y redis-server
sudo systemctl enable --now redis-server
```

Запись ключей:

```bash
redis-cli SET name Ivan
redis-cli SET city Shymkent
redis-cli SET lang python
```

Чтение всех ключей и значений:

```bash
redis-cli KEYS '*'
for k in $(redis-cli --scan); do echo "$k = $(redis-cli GET $k)"; done
```

Второй цикл выведет все ключи вместе со значениями. Если в базе есть чужие ключи, можно ограничить вывод, например `--scan --pattern 'name*'`, либо взять `redis-cli MGET name city lang`.

## Задание 5*. Работа с числами (дополнительное)

```bash
redis-cli SET key5 5
redis-cli INCRBY key5 5
redis-cli GET key5
```

`INCRBY` вернёт `10`, и `GET` покажет `"10"`. В Redis нет отдельного типа `int`: значение хранится как строка, а `INCR`/`INCRBY` интерпретируют её как число.
